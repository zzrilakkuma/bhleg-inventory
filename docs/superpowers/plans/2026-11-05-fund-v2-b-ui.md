# 公基金 V2 計畫 B：介面（帳／記／算／統計）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `/fund-v2` 做出可以取代總表日常作業的新介面：帳（B1 純帳本）、記（R1 支出／收入／轉帳）、算（S1 首頁＋四步結算精靈）、統計與應付；參與者唯讀，會計可寫。

**Architecture:** 頁面只讀計畫 A 的 view（`fund_tx_snapshots`、`fund_periods`、`fund_period_summary`、`fund_outstanding_loans`、`fund_advances_owed`、`fund_waived_total`）與基礎表；寫入沿用 `lib/fund-db.ts#insertTransaction` 的三段式寫法（交易 → 明細 → 子表）。所有可單測的邏輯（分組、凍存計算、未繳名單、請款批次、公布文字）放在 `lib/fund-v2/*.ts` 純函式，頁面元件只做排版與呼叫。角色由 `fund_roles` 決定，`member` 看不到「記」與所有寫入控制。圖表用 inline SVG，不加依賴。

**Tech Stack:** Next.js 16 App Router（client components）、Supabase JS、Tailwind 4、react-hot-toast；測試 `node:test`（`npm test`）。

**Spec:** `docs/superpowers/specs/2026-11-05-fund-v2-design.md` §5.1、§5.5（UI 全文）、§5.3（欄位語意）。草圖：`.superpowers/brainstorm/*/content/{layout,ledger-tab,settle-tab,record-tab}.html`。

計畫 C（章程規則：設定頁、未繳提醒細節、決議留痕、緊急狀態）在本計畫之後；本計畫只讀 `fund_settings` 的既有值。

## Global Constraints

- 路徑固定：`/fund-v2`（帳）、`/fund-v2/record`（記）、`/fund-v2/settle`（算首頁）、`/fund-v2/settle/run`（精靈）、`/fund-v2/stats`（統計）、`/fund-v2/payables`（應付）。首頁 `app/page.tsx` 在「公基金 流水帳」旁加「公基金 V2」入口；舊 `/fund/*` 不改。
- 三條路名稱固定為「支出／收入／轉帳」；分頁名稱「帳／記／算」。
- 每條登錄路最多三個必填；其餘收在「更多」。「記下」前顯示本筆對不凍結零用金的影響。
- 流水帳每列只顯示：日期（`stated_on ?? occurred_on`）、一句話（title 第一行）、金額、當時不凍結零用金；細節點開才顯示。
- 代墊登錄：`off_ledger=true`、`fund_expenses.claim_status='unclaimed'`、**不寫任何 fund_lines**；請款時另建 `type='expense_claim'` 交易帶 lines，原支出 `claim_status='claimed'`、`claimed_transaction_id` 指向請款交易、`claimed_on` = 請款日。放棄請款：原支出 `claim_status='waived'`，仍無 lines。
- 凍存：預設 `freeze_base='main'` × `freeze_rate`（讀 `fund_settings`），各撥一筆到兩個 reserve 科目（存放 郵局）；凍存 0 必填 `zero_reason`。
- 結算期限文字：章程 `settlement_due_day`（預設 20）；`late_days = max(0, 結算日 − 該月20日)`；同一月可再結（`period_no` +1）。
- 視覺：黑底、`#00FF41` 強調；金額 `tabular-nums`，負數 `#FF0055`、收入 `#00FF41`、其餘白；**不**全頁套等寬字、**不**用文字發光、每列不顯示快照。手機（375px）與桌面（≥1024px）都要能用：手機底部 tab bar，桌面左側欄。
- 參與者（無 `fund_roles` 或 role='member'）：看得到帳、算首頁的統計縮圖與統計頁；看不到「記」分頁、編輯／刪除、開始結算、應付的新增／標記。
- 每個 task 結尾 commit；commit 訊息結尾加 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`。
- `npm test`、`npx tsc --noEmit`、`npx next build` 全程保持綠燈；瀏覽器驗證用 `preview_start dev`（port 3001）。

## Review Focus

1. 會計在手機上登錄一筆代墊支出後，帳本小結不應改變（無 lines）；請款後才變。Task 2 測 `buildExpenseWrite` 在 advancer 時回傳 `lines: []`；Task 6 測請款批次產生的 lines 合計 = 勾選支出合計。
2. 同一天多筆登錄的順序：`seq` 必須遞增（同日最大 seq + 1），否則 view 的 `ord` 與使用者預期不同。Task 0 的 `nextSeq` 測試。
3. 轉帳從 reserve 科目搬出但未填依據 → 必須擋下。Task 4 測 `validateTransfer`。
4. 月內只剩 0 元零用金時按「30% 凍存」→ 兩筆 0 元 line 不能寫入，且 `zero_reason` 必填。Task 6 測 `computeFreeze(0)`。
5. 參與者直接打 `/fund-v2/record` 網址 → 必須被導回 `/fund-v2`，而非看到表單後寫入失敗。Task 0 的 `RoleGate` 測試＋Task 8 瀏覽器驗證。

### Task 6: 算 — 四步結算精靈

**Files:**
- Create: `app/fund-v2/settle/run/page.tsx`（步驟容器）、`steps/ClaimStep.tsx`、`steps/FreezeStep.tsx`、`steps/ReconcileStep.tsx`、`steps/PublishStep.tsx`、`lib/fund-v2/settlement.ts`、`lib/fund-v2/settlement.test.ts`
